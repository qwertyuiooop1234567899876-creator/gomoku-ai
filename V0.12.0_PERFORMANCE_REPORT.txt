Gomoku AI V0.12.0 性能实测报告
================================

测试方法
--------

基线：V0.11.0
候选：V0.12.0 Search Core 2 第一阶段
Python：3.12.13
环境：Linux x86-64（绝对时间仅代表本次容器；相对倍率更有参考价值）
重复：每个局面 3 次，比较中位数
缓存：每次运行前清空静态线评分缓存，避免跨轮预热偏差

说明
----

1. NPS 只统计 PVS 节点，完整耗时还包括 VCF、威胁画像和 ProofSearch，
   因此不能用 PVS 节点数除法解释所有局面。

2. I4 使用限时 ProofSearch。V0.12.0 的 Proof 节点中位数为 124，
   V0.11.0 约为 22；它利用同一时间切片检查了更多威胁分支，因此
   总耗时下降幅度小于其他三项，但证明吞吐量明显提高。

3. 曾实作“每步增量维护邻近候选集合”的原型。它把维护成本加到所有
   place/undo 上，H11 局面由约 1.0 秒退化到约 2.3 秒，已撤回。
   本版本只保留实测有效的局部线内核。

4. Windows 11 / Python 3.14.5 上绝对时间会不同。可运行
   run_search_benchmark.bat 生成本机 search-benchmark-results.json。
