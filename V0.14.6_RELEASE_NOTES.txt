Gomoku AI V0.14.6 Frontier Truth Order
======================================

定位
----
V0.14.6 是针对两份 V0.14.5 同根 YiXin 复盘证据的搜索正确性补丁：

  - 自对弈第8手：I9 后白方 -10000，F8 后白方 -174；两边同根、同设置、
    同为约9.97秒并完成深度10，确认 I9 是真实断崖败着。
  - 对弈 YiXin 第9手：F8 后黑方 +77，G10 后黑方 +215；差值138且两个
    子局面完成深度不同，只支持让 G10 进入候选，不支持硬指定 G10。

根因
----
多重威胁前沿模式声称在假 Mate 被隔离后保留战术顺序，但旧实现保留的是
已经被选择性假 Mate 污染过的 PVS 排名，而不是搜索前的对手威胁图顺序。
第8手的通用对手前沿顺序本来是 F8、F6、I9、I5，却被改排为 I9、I5
优先；四个候选最终 Proof 都为 UNKNOWN 时，程序因此退回 I9。

第9手的 G10 属于较低排序的安静前沿预防点。旧版只保留一个安静预防点，
G10 在根候选上限生效前就被截掉。

核心改动
--------
1. 前沿真值顺序
   - 对手威胁前沿使用搜索前的完整威胁图压力顺序。
   - 不再按本方浅层静态分重新排序对手启动点。
   - 假 Mate 降级后，只在普通启发式分相差不超过2000时保留该顺序。

2. UNKNOWN 仲裁不再覆盖已校正顺序
   - 严格 Proof 仍优先于一切启发式证据。
   - UNKNOWN 风险有实质差异时仍允许改选。
   - UNKNOWN 风险相同时，前沿模式不再按同一份浅层静态分把败着提回首位。

3. 安静预防点有界扩展
   - 根节点最多保留3个安静前沿预防点，仍受12点根候选总上限约束。
   - 第9手前 G10 进入候选，但 PVS、Proof 和最终审计仍决定是否选择它。

真实局面验证
------------
自对弈第8手前，SearchAI(d=8,t=60s)：
  - V0.14.4/V0.14.5：I9
  - V0.14.6：F8
  - 完成深度：8
  - 最终 Proof：UNKNOWN（安全性未确认，未伪造严格结论）

对弈 YiXin 第9手前：
  - G10 已进入根候选。
  - 未硬编码 G10，也未强制覆盖当前 PVS 首选。

兼容性
------
- NativeCore ABI 仍为1，不需要重新编译 DLL。
- V0.14.3 的 PVS NPS 等价加速保留。
- 坐标修复和 V0.14.5 同根复盘口径保留。

安装后验证
----------
  python -m unittest tests.test_v0146_frontier_truth -v
  python -m unittest discover -v
  python search_benchmark.py --repeat 9

最终验收
--------
NativeCore 模式：
  Ran 251 tests
  OK

纯 Python 回退：
  Ran 251 tests
  OK (skipped=5，仅跳过 NativeCore 专测)

固定基准节点数：
  counterattack_j9 = 27
  g9_multi_threat = 18
  h11_defense_vct = 48
  i4_proof_risk = 23

本机 h11_defense_vct 真正 PVS 中位：597 NPS。整手显示 NPS 仍包含候选准备、
Defense VCT、VCF 与 Proof 时间，不能代替 PVS 阶段指标。

建议重新进行一盘 SearchAI(d=8,t=60s) vs YiXin(t=10s)，并用 V0.14.5
同根复盘器检查首个实际分歧点。单盘结果仍是验证证据，不把 UNKNOWN 描述成
严格安全或严格必胜。
