Gomoku AI V0.14.8 Dynamic Remaining-Time Review
=================================================

定位
----
V0.14.8 针对 V0.14.7 对弈 YiXin 与自对弈同根复盘暴露的四个胜势兑现
断点：

  - 对弈 YiXin 第11手 F9 对 G10：G10 已在候选中，但主搜索只完成
    深度7且没有启动有效根复核；同根差 869。
  - 第13手 I8 对 D10：D10 能继续黑方进攻网络，却没有进入根候选；
    I8 使必胜局面回到均势，同根损失 10035。
  - 第15手 G7 对 G6：G6 已在候选中，但浅层风险错误偏向 G7；主搜索
    约28.8秒完成后还有大量未使用时间，同根损失 10057。
  - 自对弈第24手 J9 对 L9：L9 已在根候选中，却没有进入旧版只面向
    特殊安静兄弟点的深层复核；同根损失 9935。

本版不把 YiXin 推荐坐标写入生产代码。坐标只用于固定真实回归；候选
补全、余时分配和改选均由通用威胁结构触发。

核心改动
--------
1. 动态余时复核
   - 主搜索结束后，只有存在至少2秒可用余时时才启动根复核。
   - 可用预算为“扣除最终 Proof 保留时间与0.5秒安全余量后的剩余时间”
     的80%，上限30秒。
   - 主搜索若已运行到只剩最终 Proof 的8秒保留区，动态复核预算为0，
     不再挤占严格终审。
   - 提前完成深度8时，不再把几十秒余时直接浪费；预算用于真正竞争者
     的同窗复核。

2. 统一竞争者来源与有界决赛
   - 复核来源覆盖 PVS 前三竞争者、最低 UNKNOWN 威胁风险着、安静前沿
     预防点和进攻延续点。
   - 最多保留4个决赛来源；实际复核采用两候选同窗比较，避免把30秒
     平摊到过多候选后每一对都搜不深。
   - 主动威胁真值顺序优先保护；结构阶段已经稳定改选时，不再用后续
     浅层 PVS 重新覆盖。

3. 同窗深搜与结构净增益共同仲裁
   - 候选使用相同 alpha/beta 窗口，从深度2开始，最多复核到深度7；
     叶子允许有界的安静前沿延伸。
   - 普通、非边界分数且连续三层首选稳定时，采用同窗深搜结果。
   - 分数打平、未完成或落入选择性 +/-100000000 地平线边界时，只有
     攻防前沿净增益至少相差3000才允许结构信号改选。
   - 结构信号始终属于启发式；不会把 UNKNOWN 升级为 PROVEN_WIN 或
     PROVEN_LOSS。

4. 进攻延续桥接候选
   - 扫描本方安静进攻前沿：若一个增益点同时占据对手高等级前沿的
     后续节点，且本方至少有四路延续，则作为进攻/防守桥接点补入。
   - 最多保留4个桥接点，仍受原12点根候选上限约束，也不会挤掉已经
     入围的强制防守点。
   - 第13手 D10 因此进入真实根候选；原局面和180度镜像使用同一规则。

5. 分阶段性能画像
   - DecisionAnalysis 新增 phase_timings，分别记录 candidate_generation、
     root_vcf_scan、initial_proof、main_pvs、root_review 和 final_proof。
   - 根复核候选同时记录 frontier_balance 与 selection_basis，能够区分
     equal_window、frontier_balance 和 pvs_fallback。
   - 这些字段只增加诊断信息，不修改 NativeCore ABI。

真实局面验证
------------
同一批 V0.14.7 棋谱、SearchAI(d=8,t=60s)：

  - 第11手：F9 -> G10。
  - 第13手：I8 -> G10；D10 已进入真实根候选，完成深度8；根复核实际
    比较 I8/G10，约27.38秒；最终 Proof 仍获得8.00秒。
  - 第15手：G7 -> G6。
  - 自对弈第24手：J9 -> L9。

第13手不强制指定 D10 为唯一正确着。D10 的回归目标是补齐进攻延续
候选；最终由同窗搜索与结构证据在所有实际候选中选择 G10。

性能边界
--------
固定普通基准的 PVS 节点数仍为：

  counterattack_j9 = 27
  g9_multi_threat = 18
  h11_defense_vct = 48
  i4_proof_risk = 23

本机9次中位 NPS 分别为 719 / 502 / 312 / 19。新增逻辑位于根节点余时
复核，不进入普通 PVS 递归树。NativeCore ABI 仍为1，不需要重新编译
DLL。
