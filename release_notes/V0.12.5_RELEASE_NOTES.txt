Gomoku AI V0.12.5
Root Candidate Completeness
===========================

发布日期：2026-07-30

本版本在 V0.12.4 根候选对手 VCF 生存检查之上，修复实战记录中
暴露的根候选过度裁剪。重点是让已有 PVS、VCF 和 Proof 能看到
必要的防守与反击候选，不加入 DF-PN，不调整评价权重，也不扩大
默认 12 个根候选上限。

一、单一威胁前沿不再垄断根候选
--------------------------------

V0.12.4 在 FRONTIER_DEFENSE 模式下只搜索最强对手威胁前沿。
当最强前沿只有一个时，候选可能退化成单步，普通预防点和主动
反击点在搜索开始前即被排除。

V0.12.5 将此模式改为分来源合并：

  单一最强威胁前沿
  + 普通根排序候选
  + 我方安静活三反击点

合并由 engine/root_candidates.py 独立完成。威胁前沿和主动反击
属于必须保留的战术来源；普通候选按原有次序填充剩余位置。最终
集合仍受 root_candidate_limit=12 限制。

普通候选扩展只在“最强前沿只有一个”时启用。若已有两个以上
同级威胁前沿，仍保留原有前沿仲裁，避免浅层静态候选挤掉已经
验证过的 G9、J7、J5 等防守着。

二、主动反击不再依赖四前沿门槛
--------------------------------

V0.12.4 只有在至少四个同级威胁前沿同时出现时，才允许加入安静
活三反击点。V0.12.5 删除该触发门槛；只要进入前沿防守模式，
已经识别出的安静活三反击点就可以参与有上限的候选合并。

这项改动不把普通冲四、活三或静态高分直接升级为 Proof 状态。
所有新增候选仍需经过根 VCF 生存检查、Proof 仲裁和普通 PVS。

三、VCF 拦截覆盖整条交替线路
------------------------------

V0.12.4 只提取 VCF 主线中攻击方的 gain move。V0.12.5 改为提取
整条交替线路：

  攻击落点
  + 强制防守落点

提前占据任一线路点都可能破坏该条具体 VCF；是否真正存活仍由
逐候选对手 VCF 扫描决定，不能仅凭“在线路上”解释为安全。

当原候选和线路点合并后超过 12 步时，完整线路点优先保留，普通
候选从尾部让位。扫描次序仍优先检查线路点，最终候选数不扩张。

四、实战局面性质回归
----------------------

白 26：

  V0.12.4 候选只有 E6。

  V0.12.5 在同一 12 步上限内保留 E6，同时加入普通预防候选
  E5、H4，以及主动反击候选 J9/J10。测试只验证候选完整性，
  不硬编码最终必须选择某个坐标。

黑 25：

  当前对手 VCF 主线为：

  E10 → E12 → D10 → D9 → C11 → B12 → F11

  V0.12.5 会把该条线路的攻击点和强制防守点全部加入根扫描，
  因而不再漏掉 D9、B12 等偶数层防守点。每个点仍单独记录
  PROVEN_LOSS、SURVIVES_VCF_SCAN 或 UNKNOWN。

新增测试同时要求所有候选扫描后棋盘、历史、Zobrist Hash 和
空位数完全恢复。

六、本版本不包含
----------------

  - DF-PN 或新的长线胜负证明器；
  - 黑 23 I11 多阶段强制链的最终识别；
  - 对所有合法着执行无预算的穷举 VCF；
  - 评价权重、PVS 深度、时间比例或 NPS 调优；
  - 多线程、GPU 或界面修改；
  - 新对局实战结论。

建议验证顺序：

  python -m unittest discover -v
  python search_benchmark.py --repeat 3

本地测试通过后，再使用 V0.12.5 进行新对局实战验证。
