Gomoku AI V0.14.2 YiXin Review Coordinate Fix
================================================

定位
----
V0.14.2 是 V0.14.1 的复盘准确性修复版。本版不修改 SearchAI 搜索、
候选生成、Proof 预算、评价权重或 NativeCore DLL。

根因
----
YiXin 有两种坐标输出：

1. 最终落子的 Gomocup 数字坐标 x,y；
2. DETAIL / BESTLINE 的人类可读坐标 [字母,数字]。

后者基于 YiXin 棋盘显示方向，相对本项目棋谱坐标旋转了90度。旧解析器将
两种格式当成同一坐标系，造成完成层主线首着与最终返回着全盘不一致，
部分主线首着甚至落在已有棋子上。

修复内容
--------
1. 对 DETAIL / BESTLINE 方括号坐标实施明确的90度转换；数字 x,y 返回着
   保持原有 Gomocup 解析。
2. 区分“最终返回着”、“最后完成层主线首着”和“完成层局面分数”；
   对齐状态只作诊断，不再将完成层分数删除。
3. 移除基于错误坐标结论添加的“未对齐 Mate 带必须在下一局面保持”规则。
   如果下一手退出 ±10000，复盘应如实记录为优势未兑现，而不是判为不可比。
4. 报告格式升级为 1.3，新增 first_decisive_blunder_by_player，分别记录黑方和
   白方的首个断崖败着，避免一方更早的失误遮住另一方的关键败着。

实战报告验证
------------
- V0.14.1 SearchAI 自对弈满盘和棋：224/224 个含完成层主线的局面与最终返回着
  完全对齐，转换后非法/已占用首着为0。
- V0.14.1 SearchAI 对弈 YiXin：23/23 个含完成层主线的局面与最终返回着完全对齐，
  转换后非法/已占用首着为0。
- 对弈 YiXin 的报告可分方识别：YiXin 白方第12手 D12 首次进入必败带；
  SearchAI 黑方第17手 G7 首次进入必败带。
- 自对弈报告的全局首个断崖败着为第10手 J5；后续多次进入和退出必败带，
  证实“满盘和棋”主要是双方反复获得并错失胜势，而不是单纯的极端防守。

验证结果
--------
- 专项测试：Ran 22 tests / OK
- 完整回归：Ran 237 tests / OK
- Python 语法编译检查：OK

安装与复盘
----------
将增量 ZIP 放到现有 V0.14.1 项目根目录后覆盖解压。不需要重新编译 DLL，
不要运行 build_native.bat。

PowerShell 验证：

  python -m unittest tests.test_yixin tests.test_cvc_analysis -v
  python -m unittest discover -v

完整测试必须显示：

  Ran 237 tests
  OK

安装后需用原始 CVC JSON 重新运行复盘；旧的 yixin-analysis JSON/TXT 不会自动改写。
