Gomoku AI V0.14.5 Paired YiXin Review Truth
================================================

定位
----
V0.14.5 是复盘正确性补丁，不修改 SearchAI 搜索、候选、评分、Proof、VCF、
NativeCore 或 NPS 优化。它先修复用于决定下一步棋力补丁的证据口径，避免把
两次深度和提前终止状态不同的 YiXin 搜索直接相减后，反向修改 SearchAI。

根因
----
旧复盘用“落子前局面评价 -> 实战落子后局面评价”计算损失。这两个评价来自
相邻局面的两次独立搜索，可能完成于不同深度，也可能一边因临时 ±10000 提前
结束。因此即使实战着等于 YiXin 推荐着，也可能被标为“直接败着”。

V0.14.4 自对弈报告中的典型现象：
  - 第8手 I9 后，YiXin 很快报出白方 -10000；
  - 第9手黑方走 YiXin 自己推荐的 F8 后，评价又回到约 -239；
  - 旧报告仍把第8手定性为白方断崖败着，并把第9手的推荐一致着也计入巨大
    损失。

这不足以证明 I9 一定输给 F8，也不能作为强制 SearchAI 改选 F8 的依据。

核心改动
--------
1. 同根双子局面对照
   - 实战着与 YiXin 推荐着不同时，从同一个落子前棋盘分别落下两着。
   - 两个子局面使用同一 YiXin 配置和相同时间上限重新搜索。
   - 损失只比较“实战着后评价”和“推荐着后评价”，不再比较相邻根局面。

2. 推荐一致不再被归罪
   - 实战着等于 YiXin 推荐着时固定标为“推荐一致”，损失记为0。
   - 后一个独立局面即使发生 ±10000 跳变，也不会把推荐着误判为直接败着。

3. 无法构造同根对照时保持未知
   - 推荐坐标缺失、无效或已占用时，记录“无法同根比较”。
   - 不再退回旧的相邻局面差值并生成伪精确结论。

4. 报告格式升级到1.4
   - 表格改为“实战后/推荐后”。
   - JSON 新增 evaluation_after_recommended_white、comparison_basis、
     paired_comparison_completed 及推荐子局面的深度、选择深度、耗时和主线。
   - “首个断崖败着”和“最大损失”只使用新的同根证据。

保持不变
--------
- engine/search.py 与 V0.14.4 字节一致。
- 不修改 SearchAI 落子，不预设 I9 或 F8 谁正确。
- 不修改根候选，因此不会用尚未验证的复盘结论扩大搜索树或降低深度。
- NativeCore ABI 仍为1，不需要重新编译 DLL。
- V0.14.3 的 PVS NPS 加速完整保留。

验证
----
  python -m unittest tests.test_cvc_analysis -v
  python -m unittest discover -v

NativeCore 模式：
  Ran 248 tests
  OK

纯 Python 回退：
  Ran 248 tests
  OK (skipped=5，仅跳过 NativeCore 专测)

建议先做的定点复盘
------------------
自对弈第8手：
  python cvc_analysis.py records\search-d8-t60-vs-search-d8-t60-v0144-20260802-182820-466594.json --from-move 8 --to-move 8 --time-limit 10

对弈 YiXin 第9手：
  python cvc_analysis.py records\search-d8-t60-vs-yixin-t10-v0144-20260802-181600-702415.json --from-move 9 --to-move 9 --time-limit 10

只有当新报告在同根对照中仍稳定显示 I9 明显差于 F8，才应把该局面用于下一版
UNKNOWN 候选仲裁回归；G10 也应以同样的同根对照确认真实差距后再调整候选策略。

安装
----
在已经通过246项测试的 V0.14.4 项目根目录覆盖解压。不需要运行
build_native.bat。复盘中每个“实战着 != 推荐着”的局面会多进行一次 YiXin
子局面搜索，因此整盘复盘时间可能增加；使用 --from-move/--to-move 可先定点
验证关键手。
