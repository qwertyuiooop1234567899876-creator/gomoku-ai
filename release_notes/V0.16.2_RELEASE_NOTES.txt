Gomoku AI V0.16.2 Full CVC Workflow
===================================

新增流程
--------
新增 run_cvc_workflow.bat，按固定顺序自动完成：

1. SearchAI(d=8,t=60s) 对 SearchAI(d=8,t=60s)。
2. 使用 YiXin 分析刚刚生成的自对弈 JSON 棋谱。
3. SearchAI(d=8,t=60s) 黑方对 YiXin(t=10s) 白方。
4. 使用 YiXin 分析刚刚生成的人机对弈 JSON 棋谱。

可靠性
------
- 总控程序直接使用每盘 play_game 返回的 RecordPaths.json，不按目录时间猜测文件，
  因此不会误分析旧记录。
- 每一步成功后才进入下一步；任意对局或分析失败都会停止流程并返回非零退出码。
- BAT 成功时自动关闭，失败时保留窗口并暂停，便于查看错误。
- 原 run_arena.bat 和 run_cvc_analysis.bat 保留为独立手动入口。
- 原 run_yixin_cvc.bat 已由完整流程入口替代并删除。

根搜索修复
----------
- 根候选会在完整相关点集合上批量补齐己方强制胜点、冲四和活三画像，
  战术来源不再受普通快速排序前缀限制；PVS 根宽度仍保持原上限。
- 未证实优势触发的 root_expansion 只作为挑战者。扩展着法必须与原候选完成
  独立等窗复核，或由后续严格 Proof 排除原候选，才能接管最终选择。
- 扩展搜索会预留串行根复核和最终 Proof 时间，避免新增候选耗尽全部 60 秒预算。

项目结构整理
------------
- 用户应用实现统一放入 app/，构建、复盘和基准工具实现统一放入 tools/；
  根目录保留轻量兼容入口，原 BAT、命令行和测试 patch 路径无需改变。
- 搜索诊断记录构建与结束原因拼装移入 engine/search_diagnostics.py，
  SearchAI 保留搜索协调与 PVS/Negamax 热路径，避免用高耦合 mixin 机械拆分。
- 新增根目录 README、架构边界说明和兼容入口结构测试；records/ 继续只作为
  本机运行数据目录，结构整理不会恢复或重建历史棋谱。
