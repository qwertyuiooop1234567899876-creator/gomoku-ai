Gomoku AI V0.16.9 Search Evidence Baseline
===========================================

问题来源
--------
- V0.16.8 的 Final-Proof 紧急 VCF 结果会合并进常规根 VCF 记录，
  无法判断紧急切片是否尝试、检查了哪些候选、是否实际改变选着。
- 动态复核已记录 finalists 和实际 pair，但缺少 finalist 未进入 pair
  的原因及剩余预算，复盘仍需从节点数和队列顺序猜测。
- 第 13 手 F7/J11 的深度 8～10 基线持续偏向 F7，证明加速或多一两层
  不是充分修复；需要把主 PVS、安静前沿和 Defense VCT 分渠道消融。

审计补全
--------
- Final-Proof 紧急 VCF 独立记录 attempted、预留/实耗时间、有界候选
  状态、完成性、节点、耗时、截止原因及门禁前后选着。
- changed_selection 只表示紧急门禁相对无门禁 emergency fallback 的
  真实改变；普通 Final Proof 的 strict/UNKNOWN 改选不会误归因于它。
- UNKNOWN 保持 UNKNOWN，新增字段不改变 Proof、VCF 或最终选着策略。
- 动态复核增加 unpaired_finalists，记录未进入 pair 的候选、原因和
  剩余预算；已进入但未完成的 pair 仍由原 pair trace 表达。

语义实验基线
------------
- full-window 可显式设置威胁延伸深度和非根分支上限，并按需输出有界
  候选层摘要、叶面返回分类、PV、节点、延伸和完整 TT 摘要。
- trace 默认关闭；默认路径继续实例化普通 SearchAI，不给历史性能
  基线增加追踪开销。
- 安静前沿只在 dynamic-pair 模式运行，Defense VCT 使用独立模式，
  不伪装为主 PVS 参数。
- 深度 8 矩阵显示延伸和宽度显著改变分数与节点，但仍不足以形成
  通用搜索不变量违例，因此本版不调评估权重或默认搜索参数。

结构回归
--------
- 覆盖紧急门禁未尝试、UNKNOWN 保留首候选、首候选证败后换下一候选、
  候选明细截断及序列化。
- 覆盖普通 Final Proof 改选不会让 emergency changed_selection 误报。
- 覆盖真实动态复核预算不足时，所有未进入 pair 的 finalist 都有原因。
- 覆盖 trace 显式启用、默认零开销路径、dynamic-pair 分支参数传递及
  固定节点/有序历史基线不变。

非目标
------
- 不修改根候选成员、PVS/Negamax、Proof 三态、VCF 结论、评估权重或
  默认延伸/分支参数。
- 不把 J11 写成严格唯一正确着；Native 初版仍以 Python 语义等价为门禁。
- 不恢复、生成或提交 records 中的历史或本机对局文件。

验证结果
--------
- Sol/Terra 聚焦组首轮 36/36 通过；紧急门禁因果修正后根级复跑
  34/34 通过，无失败、错误或跳过。
- 全量 unittest：406 项中 405 通过；唯一失败来自工作区根目录 6 个
  受保护的未跟踪临时 Python 脚本触发目录整洁断言，非源码逻辑失败。
- 固定搜索基准保持 J9/G9/H11/J5，节点数 32/19/48/23。
- git diff --check 通过；当前环境无 C++ 编译器，未宣称完成 Native
  整体搜索下沉。
